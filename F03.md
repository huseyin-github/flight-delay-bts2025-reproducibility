# GitHub'a yükleme — Türkçe kısa rehber

1. `Flight_Delay_BTS2025_GitHub_Reproducibility_Package.zip` dosyasını bilgisayara indirin ve **klasöre çıkarın**. ZIP dosyasını doğrudan depoya yüklemeyin.
2. GitHub hesabınızdayken https://github.com/new adresini açın.
3. **Repository name:** `flight-delay-bts2025-reproducibility` · **Visibility:** Public · **Add a README:** kapalı (pakette README var). **Create repository** seçin.
4. Depo sayfasında **uploading an existing file** bağlantısını veya **Add file → Upload files** seçeneğini açın.
5. ZIP'ten çıkardığınız `flight-delay-bts2025-reproducibility` klasörünün **içindeki bütün dosya ve alt klasörleri** yükleme alanına sürükleyin. `README.md`, `.gitignore`, `CITATION.cff`, `scripts/`, `results/`, `docs/`, `data/`, `tools/` dahil olmalı. Sonra **Commit changes**.
6. `README.md` ana sayfada görünmeli. `scripts/main/Stage27_All23Presets_FullData_5Fold_Exact.m` dosyasına tıklayarak kodun açıldığını kontrol edin.
7. Adres çubuğundaki **gerçek herkese açık depo adresini** kopyalayın ve makalenizin **Code Availability** bölümüne, ayrıca hakeme yanıt dosyasına ekleyin. İlgili İngilizce metinler `docs/REVIEWER_CODE_AVAILABILITY.md` içindedir.

**Dikkat:** Ham `TranstatsData_Ayse4.xlsx` ve `Stage27_Full23_Checkpoint.mat` dosyalarını eklemeyin. Sonuçları yeniden üretmek için aynı BTS veri sürümüne erişim gerekir. Repo bunların var olduğunu iddia etmiyor. Yayımlanmamış kaynak veri özdeşliği ve Stage26 denetiminin eksik bağımlılıkları için `docs/PUBLISHING_CHECKLIST.md` dosyasına bakın.

Bu repo yayımlandıktan sonra dergi başvuru ekranına GitHub bağlantısını girin. Depo **Private** kalırsa hakem/okur bağlantıyı açamaz.
