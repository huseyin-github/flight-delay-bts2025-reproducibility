# Flight arrival-delay prediction — January 2025 BTS data

**Reproducibility materials for** *Artificial Intelligence-Enabled Decision Support for Air Transportation: Evidence from Machine Learning-Based Flight Delay Prediction* (manuscript submitted to *Frontiers in Built Environment*).

This repository documents the MATLAB implementation, fixed temporal-validation design, computational constraints, and reported results for an observational **post-departure arrival-delay regression** analysis of U.S. Bureau of Transportation Statistics (BTS) data for January 2025.

## Key findings and reporting scope

- Source extract reported by authors: **599,013** flights; eligible non-cancelled/non-diverted flights: **578,957**.
- Development period **Jan 1–24 (447,066)**; later-period test **Jan 25–31 (131,891)**.
- Five expanding-window development validations yield **274,691 non-overlapping OOF predictions**.
- **23** original MATLAB Regression Learner presets are documented, **16** completed all five folds, with **82 of 115** model/fold fits completed.
- Best pooled model among those 16 by RMSE and MAE: **Robust Linear** (RMSE **15.259 min**, MAE **10.516 min**, R² **0.93033**).
- The seven incomplete presets do **not** receive pooled scores; two exact GPR variants were memory-blocked. None of these facts establishes statistical or universal superiority.

## How to run the primary analysis

1. Install MATLAB **R2024b or a compatible later release** with **Statistics and Machine Learning Toolbox**. Native full-data SVM fits may take many hours or longer; exact GPR needs unusually large memory.
2. Obtain the exact January 2025 BTS source extract described in [`data/README.md`](data/README.md). Save it as `TranstatsData_Ayse4.xlsx` with worksheet `TranstatsData_Ayse` and the specified fields. The author's frozen source workbook was not supplied with this repository.
3. To recompute the training-set mean, training-set median and direct departure-delay reference models, run `scripts/main/Stage00_SimpleReferenceModels.m` first. This standalone script generates `Stage00_ReferenceModels/Stage00_Baselines.csv` beside the selected workbook.
4. In MATLAB, open `scripts/main/Stage27_Resume_Defer_Both_KAR_And_SVM.m`. Run it and choose the workbook when prompted. This version executes manageable native full-N configurations and explicitly defers costly kernel/SVM models. It writes checkpoints and CSV outputs beside the selected Excel file under `Stage27_Full23_5Fold/`.
5. To perform **all attempted original configurations without scheduling deferrals**, run `scripts/main/Stage27_All23Presets_FullData_5Fold_Exact.m` on appropriate hardware. The exact-GPR memory guard prevents unsafe allocation. The scripts store a source path/size/timestamp fingerprint: restarting with a different path or modified workbook requires a new checkpoint.
6. For the completed native full-N SVM comparisons, the saved historical run sequence used `Stage28_*` (Linear SVM, #11) and `Stage29_*` (Quadratic SVM, #10). These scripts preserve the same Stage27 project/checkpoint tag and use all training rows. Run on a clean input folder when starting from scratch; when resuming, use the exact same workbook and checkpoint folder.
7. At completion, compare `Stage27_All23_PooledOOF.csv` / `Stage27_All23_FoldResults.csv` with the transcribed summaries in [`results/`](results/). Console-transcribed values are rounded; native exports retain greater precision.

A run cannot reproduce the authors' exact numerical results unless the input source is the same and the MATLAB/hardware/solver environment is comparable. A stable public frozen input link and checksum were **not available** when this archive was assembled; see the publishing checklist.

## Primary protocol versus supplemental analyses

The principal Table 9 numbers are from **native full-data five-fold MATLAB** fits, *not* from Stage20/Stage23 exploratory implementations. Stage23's SVM sample cap, sparse GPR active set and bounded kernel-feature expansion must not be described as native full-N fits. The auxiliary Jan 25–31 robust-regression audit (RMSE **13.062 min**, MAE **9.283 min**) is **a different numerical implementation** (sparse-QR IRLS) and is not the same fit as the `fitlm` Robust Linear entry in the pooled native benchmark. The later test was inspected during numerical auditing and is not a fully untouched external holdout.

No separate grid search, random search or Bayesian hyperparameter tuning was undertaken. Some presets have parameters set to `auto` by the native MATLAB routines.

## Data availability and reuse

The BTS data are accessible from the official [BTS TranStats portal](https://www.transtats.bts.gov/). The authors' original workbook, row-level outcomes, prediction checkpoints and personal local file paths are intentionally not published in this code-only archive. See [`data/README.md`](data/README.md).

The research manuscript and this repository should be cited together. No separate software license is granted by this archive unless the authors add one.
